most detailed record of what each version changed and existed nowhere else in the
repository. It is tracked here so it survives a fresh clone.

| 0.7.28 | K | **Atmospheric effects rewrite + CRT background.** The old overlay built one `LoopAnimationBuilder` and one full-screen `CustomPaint` *per particle* (fireflies nested a second controller inside the first), so defaults meant ~80 animation controllers and ~80 compositor layers per frame, each doing a `MaskFilter.blur` gaussian. The ticker stops entirely when no effect is enabled. Motion is now closed-form in `t` (resolution independent, resumable, unit-testable). **Motes:** depth-based parallax, two-term sine wander instead of a straight A-to-B lerp, twinkle. **Rain:** one shared wind slant for the field (was derived per drop from its own length, so drops crossed at different angles), streak length proportional to fall speed, depth layering, visible opacity. **Fireflies:** no longer a recoloured mote. Text is deliberately excluded so glyphs stay flat and crisp. Falls back to a plain `BoxFit.cover` image if the platform cannot compile the shader. | done |
| 0.7.28.1 | K | **CRT reworked around fuzz; effect sliders are real counts.** 0.7.28 shipped the CRT as a background-only barrel warp, so raising intensity just deepened a fisheye wallpaper while text stayed untouched. The shader now leads with analog artifacts (seven-tap horizontal smear for lost bandwidth, bloom bleed from bright areas, colour separation growing toward the edges, rolling scanlines, aperture grille, per-frame grain, stronger vignette); barrel distortion is capped at `0.045` so curvature is felt, not seen. Sliders are percentages of `kMaxMotes` / `kMaxRainDrops` / `kMaxFireflies`, so 50% always draws the same first half and raising the value only adds particles. | 0.7.28.2 | K | **Fix frozen chat under CRT; split scanline and fisheye controls.** 0.7.28.1 used `SnapshotWidget`, which caches its raster: its painter's `notifyListeners` repaints "re-using the same raster" by design, and children behind a `RepaintBoundary` (the message list and effects overlay both are) never mark it dirty. The chat therefore froze at the first frame while scanlines kept rolling. Replaced with a `RenderProxyBox` (`_RenderCrtEffect`) that paints the child into a detached `OffsetLayer` and `toImageSync`es it **every** frame, mirroring the framework's own `_paintAndDetachToImage`. Content is live again; the cost is a full-surface rasterise per frame, inherent to a live post-process. Falls back to painting the child untreated when a subtree cannot be rasterised. **New controls:** `CRT Scanlines` slider drives scanline and aperture-grille visibility from its own uniform, independent of master intensity, so at 0 the raster structure disappears and only the signal artifacts (smear, bloom, chromatic aberration, grain) remain. `CRT Fisheye` switch gates the barrel warp entirely; off by default, and when off the sampling grid is untouched at any intensity. | 0.7.29 | L | **Background completions reach disk; web search streams again.** Two unrelated defects that both made a conversation read as shifted by one turn or feel dead. **Persistence:** `SessionService.finalizeBackgroundSession` and `addMessageToSavedSession` mutated `savedSessions` and returned without calling `persistSessions()` or `onStateChanged()` — every other mutator in the file does. A reply that landed while its conversation was not the active one existed only in memory, so on restart the prompt was followed by the empty assistant message that seeds a stream (`AUDIT-0.8-ADDENDUM.md` 2.2). That blank bubble renders as a gap, putting every later reply one slot below the message that prompted it. Both now persist. Added `SessionService.dropEmptyAssistantPlaceholders`, applied in `loadSessions`, which repairs conversations already damaged on disk; it keeps any assistant message carrying text, images, usage or regeneration history. Autosave is a 600 ms debounce and nothing flushed it on the way out, so a close inside that window dropped the last turn: `AIRP` is now a `StatefulWidget` with a `WidgetsBindingObserver` calling `ChatProvider.flushPendingSave` on paused/hidden/detached, backed by `SessionService.flushPendingSave`. Reasoning was also being lost outright: the detection call never set `include_reasoning`, which OpenRouter requires, and `performGeminiFunctionDetection` never checked `thought: true`, concatenating Gemini's thinking into the visible answer as prose — now split via `splitGeminiThoughtParts`. That Gemini request also carried no `generationConfig` at all, silently discarding temperature/topP/topK/maxOutputTokens on every turn with web search on. The search-progress bubble now shows queries already run plus the in-flight one with a round counter instead of overwriting a single line. History limiting was applied only on the plain send path, so enabling web search sent the entire conversation; both paths now share `_limitedHistory`. Adds `async` as a direct dependency for `StreamQueue`. | done |
| 0.7.29.1 | M | **Token counting anchored to reported usage; usage badge fixed.** The context meter shipped in `0.7.26` measured something the app never sent. Its estimate branch summed the raw `_systemInstruction` field, so the character card, persona, recognized lore, depth prompts and the web-search hint — everything `PromptPipelineService.buildSystemInstruction` assembles — were invisible to it, while both branches walked the entire conversation and ignored `historyLimit`, over-counting in the other direction. Meanwhile the exact `prompt_tokens` every provider reports arrived each turn, was rendered in a badge, and was then discarded. New `lib/utils/token_utils.dart`: the meter is now anchored to the last reported `prompt_tokens` and estimates only what was added since, scaled by a per-provider calibration ratio (`airp_token_calibration`, EMA-smoothed, clamped to 0.5–2.0) that converges on the provider's own accounting after one exchange. The anchor delta may be negative, so deleting or shortening a message inside the anchored window shrinks the meter. `loadSession` re-anchors from the most recent stored usage reading. The Gemini branch's `_model.countTokens` round trip is gone: it cost a request per turn, needed a valid key, and left a silently stale number on `debugPrint` whenever it failed. The estimator drops the `+0.3 tokens/word` term, which double-counted on top of an already space-inclusive chars/4 rate, and images are charged at Gemini's 258/tile rather than a flat 200. **Usage badge:** `chat_api_service` forwards Gemini's camelCase `usageMetadata` verbatim but the widget read only OpenAI snake_case keys, so every Gemini turn displayed `0 in + 0 out = 0 total`. `TokenUtils.normalizeUsage` maps Gemini, `input_tokens`/`output_tokens` gateways and nested `*_details` objects onto one shape, surfacing reasoning and cached counts; it also runs on read, so sessions saved by older builds render retroactively. Gemini's `candidatesTokenCount` excludes thoughts, which are added back so `completion_tokens` includes reasoning as OpenAI defines it. The meter now refreshes on delete, edit, session load and provider switch instead of only at end of stream, and the `enableGrounding` guard that froze it permanently once Gemini grounding was on is removed. `LorebookService` delegates to the shared estimator, replacing a 1.3-tokens-per-word heuristic that ran about a quarter low and let budgeted entries overshoot. ## Key decisions

Preserve these across context compaction.

*   **Reasoning:** persist in session JSON for redisplay; strip the thinking tag
    ONLY from the outbound LLM payload, never from displayed or stored text. The
    per-bubble "Show Thought Process" chip stays; no new input-area control.
*   **Summarize branching:** the new conversation is [narrative summary] + [voice
    samples] + [last N assistant/user pairs]. The slider counts assistant turns and
    pairs are anchored on the assistant side. The original conversation is untouched.
*   **Config Packs:** capture ALL settings-drawer state except conversations and API
    keys. SillyTavern support is IMPORT-ONLY. The old per-rule store was discarded
    with no migration.
*   **Web search:** no Smart/Eager modes. Tell the LLM it has the tool with the
    configured limits and let it decide. Reasoning must remain visible during tool
    calls.
*   **Lore:** history scanning was removed deliberately in `0.6.11.1` and is not
    coming back without an explicit decision. Current-input recognition is the whole
    feature. See the lore section in `ARCHITECTURE.md`.
